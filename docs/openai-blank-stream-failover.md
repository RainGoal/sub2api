# OpenAI 空白流失败切号

## 行为与适用范围

上游可能先发送 assistant 空文本占位及空格，再返回 HTTP 200 中的
`response.failed`。开启本功能后，已验证的前导空白暂存于当前尝试中，
可重试失败仍由现有账号调度与重试预算处理；失败尝试的占位事件不发给客户端。

覆盖 OpenAI Responses 普通 HTTP 转发、HTTP 透传及 HTTP→WebSocket 桥接的
首回合。原生 WebSocket 上游及桥接后续回合不扩大现有重放范围。

- 只识别同一 assistant 消息、同一内容索引的标准空文本生命周期。
- 空白仅包含 ASCII 空格、制表符、回车和换行；不删除或 trim 正常内容。
- 正文到达立即按顺序放行，保留所有原始空白与格式。
- 推理、拒绝、工具调用、媒体、未知字段或事件出现后，不允许本策略重放。
- `response.failed` 自带的输出也会检查；包含正文、工具或不确定内容时禁止重放。
- 请求声明了上游托管或未知工具时，不启用新增的空白重放策略。
- 合法空白响应正常完成时保留成功终态；只有空消息结构、不含内容或用量的
  空成功响应仍按已有规则处理。
- 纯空白阶段累计暂存上限为 256 KiB。首次确认空白文本 part 后最多等待
  30 秒；已有首输出截止时间更早时优先生效，空格和心跳不延长截止时间。
- 空白超时沿用现有首输出超时错误及切号预算；客户端取消不触发重放。
  正文已开始后的断连用量收尾沿用原逻辑。

## 灰度开启与回退

管理端「设置 → 网关 → 协作任务兼容处理」新增「空白流失败切号」。
对应字段是 `openai_collaboration_settings.blank_stream_failover_enabled`，
默认 `false`，旧配置缺失此字段也按关闭处理。

启用需要同时打开该子开关与兼容处理总开关，并选择已有分组/API Key 范围。
它独立于明文适配及旧密文恢复，不要求开启这两个子功能。
旧密文的 `blank_prelude_wait_seconds`（2–15 秒）不控制普通空白流切号。

先对指定分组和测试 API Key 开启，观察空白后失败的切号结果、最终成功率、
首个有效输出耗时及上游失败记录。关闭子开关即可回退此功能，关闭总开关也会禁用它。
各请求/WS 回合读取配置快照，正在处理的请求不因开关变动改变语义；
新的请求在已有设置缓存刷新后应用修改（缓存 TTL 2 秒）。

无数据库迁移，无需改动生产数据或代理路由。升级应用版本后配置仍默认关闭。
对未知供应商协议采取保守透传，因此不能保证所有非标准空白流都能自动切号。

## 回归验证

新增 `openai_blank_stream_guard_test.go`、`openai_blank_stream_forward_test.go`
和 `openai_blank_stream_routes_test.go` 覆盖单空格、连续空白、空文本、失败终态
含正文/工具、工具与推理启动、未知字段、正常空白格式、开关与范围、取消、
绝对截止、缓冲上限及下一账号不泄漏失败帧。

发布前执行后端全量、全包 unit、lint、前端 typecheck/test/build、内嵌资源检查；
Docker 集成测试和安全扫描必须在对应提交的 CI 中通过后才发布版本 Tag。

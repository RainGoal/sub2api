# 上游余额监控

管理端独立页面 `/admin/upstream-balances`，用于集中查看多个上游 Sub2API
钱包的余额和充值入口。它不参与模型请求、计费、账户倍率或渠道调度。

## 使用方式

1. 在“上游余额”中发现现有 API Key 接入账户的站点。
2. 添加钱包。确认该站点只有一个上游账号时，勾选所有 Key 共用钱包；
   同站点后续新增的 Key 会自动归入该监控项。
3. 同站点有多个上游账号时，分别建立钱包并选择各自的接入账户。
4. 查询 Key 可自动选择，也可指定一个现有接入账户。配置低余额阈值和充值链接。
5. 先手动刷新验证余额类型，再按需开启自动刷新（默认关闭、周期默认 1,800 秒）。
   周期支持 10～86,400 的整数秒，例如 10、15、30 秒；原有分钟配置按相同实际时长读取。

周期从每次查询完成后计算。查询较慢、钱包较多或有其他实例查询时，实际更新可能晚于配置周期；
仍最多同时查询两个钱包，不通过增加并发追赶。缩短周期后，已有快照按新周期重新计算到期时间。
管理页定期读取本平台余额缓存，不直接触发上游查询；自动开启时按 10～60 秒更新缓存显示，
关闭时保持 60 秒低频读取，页面隐藏时暂停读取，离开页面后停止。

“单账号”仅归并监控关系，不合并、修改或删除实际接入账户。
不同子域名、协议、非默认端口及不同部署子路径分别识别，常见末尾 `/v1` 会规范化。
同一站点的单账号模式与多个手动钱包互斥；手动钱包的账户集合不能重叠。
关闭单账号模式并手动分配账户，可拆分钱包。

## 数据含义

查询接口为上游 `GET /v1/usage`（保留部署子路径），使用已保存的 Key。
各上游版本可能不同，接入时必须验证实际响应：

- 只有明确返回的钱包 `balance` 才用于钱包余额和低余额判断。
- `quota_limited` 代表 Key 额度，订阅响应代表套餐额度，均单独标记。
- 查询失败保留最后一次成功值，并显示查询状态和最后成功时间。
- 当前有效的正常余额显示绿色，低余额显示琥珀色，查询失败或过期的历史余额显示灰色。
- 未查询、查询失败、过期及不支持都不等于余额为零。
- 首版接受 Sub2API 明确返回的 USD 钱包余额；未知单位视为不兼容响应。
  充值阈值使用 USD，不做币种换算或钱包总额累加。

自动选 Key 会进行有界尝试，优先复用此前成功返回钱包余额的账户。
无法通过现有 Key 取得钱包余额时，应指定合适的查询 Key；不会通过登录或修改上游配置绕过限制。

## 开发边界

- 独立 service、repository、管理端 handler、页面与 API 模块。
- 配置和快照使用独立的 settings 键；不更新现有账户、分组、倍率、调度状态。
- 只引用账户 ID，不在监控配置中复制 Key，管理接口不返回凭据或上游原始响应。
- 独立 HTTP 客户端实例和并发额度；沿用现有 URL 校验、代理及禁止重定向机制。
- 自动刷新默认关闭；关闭时停止周期查询，管理员手动刷新仍可使用。
- 秒级调度按到期时间等待，最长 60 秒检查一次跨实例配置变化；关闭或长周期时不逐秒扫描账户。
- 同一钱包保留 10 秒最短查询间隔；只修改余额监控周期，不调整其他后台任务的周期。
- 配置使用版本号防止并发覆盖；查询期间配置或凭据变化时丢弃旧结果。
- 查询有超时、响应大小、尝试次数和批次上限，多实例使用独立锁。
- Redis 协调锁不可用时暂停查询，不回退占用数据库 advisory lock 连接。
- 不自动停用账户、不自动充值、不发送外部通知、不收集余额历史。
- 无数据库 schema 迁移；无需修改原有账户或用户端配置。

## 管理接口

均使用现有 `/api/v1` 响应格式，并继承管理员认证、管理端限流、合规与审计中间件。
这些接口不挂载到用户端或模型网关。

| 方法 | 路径（相对 `/api/v1`） | 用途 |
| --- | --- | --- |
| GET | `/admin/upstream-balances` | 配置与余额快照 |
| GET | `/admin/upstream-balances/discovery` | 站点及账户 ID/名称，不返回密钥 |
| PUT | `/admin/upstream-balances/config` | 按版本保存独立监控配置 |
| POST | `/admin/upstream-balances/:id/refresh` | 手动查询单个钱包 |

配置包含 `version`、`enabled`、`interval_seconds`、`wallets`。
`interval_seconds` 为 10～86,400 的整数，默认 1,800。
旧配置或客户端仅提供 `interval_minutes` 时保留原周期（5～1,440 分钟）；
同时提供两个字段时以秒为准，读取旧配置不会写入数据库。
响应保留兼容分钟字段；秒周期不足 5 分钟时，兼容值为 5 分钟，回退旧版本后不会进行秒级查询。
钱包包含 `id`、`name`、`site_url`、`single_account`、`account_ids`、
`query_account_id`、`threshold`、`recharge_url` 和 `enabled`。
两个 `enabled` 分别控制全局和单钱包自动查询。

错误沿用 HTTP 状态码及结构化 `reason`：400 配置错误、401 未登录、403 非管理员、
404 钱包不存在、409 配置/凭据冲突或查询正在进行、503 服务不可用。
上游查询失败作为监控结果返回，不修改接入账户状态。

## 部署与验收

正常构建后端与内嵌前端即可发布；此功能没有必须打开的后端开关。
升级后默认不会向上游发起周期请求。原来的倍率探测开关与本功能独立。

上线后检查：管理员可打开页面；普通用户访问四个接口均被拒绝；
同钱包多个 Key 只显示一行；同站点新增 Key 自动关联；多账号模式可拆分；
充值链接打开正确站点；Key 限额不显示成钱包余额；失败保留旧值且标记状态；
关闭自动刷新后无周期请求；模型调用和现有账户配置保持原行为。

回退到不含余额功能的应用版本后，独立 settings 键可以保留，该版本不会读取这些键。
回退到仅支持分钟的余额版本时使用兼容分钟值，秒周期会向上取整且至少为 5 分钟。
发布前需完成仓库要求的前后端测试、lint、构建和有 Docker 的集成测试。

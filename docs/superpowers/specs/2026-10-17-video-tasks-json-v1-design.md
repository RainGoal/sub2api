# Video Tasks JSON v1：供应商接入、模型目录与视频计费

日期：2026-10-17。状态：待审设计，不代表接口已经实现。基线：`03c3c50cc`。

## 1. 目标与方式选择

完整覆盖 BBLabu 当前 33 个视频型号，允许同协议供应商使用自定义 URL/名称；获取实际 Key 可用型号；支持按秒与按成功视频条数计费；保留现有任务和客户端。

| 方式 | 结果 | 决策 |
| --- | --- | --- |
| 只扩大模型名白名单 | 无法处理字段差异、新分辨率、按条售价及编号冲突 | 不足以完成需求 |
| 统一协议适配器、模型能力目录、显式计费单位 | 复用现有任务、调度、鉴权和结算 | 采用 |
| 可编程任意字段脚本、通用供应商引擎 | 引入额外复杂度与执行风险 | 不纳入 |

## 2. 协议和账号

显示名称 **Video Tasks JSON v1**，新标识 `video_tasks_json_v1`。协议要求 Bearer Key、JSON 创建、任务 ID、状态轮询及内容获取；BBLabu 是首个预设，不称其为行业统一标准。

| 操作 | 上游约定 |
| --- | --- |
| 创建 | `POST {base}/videos`，JSON |
| 查询 | `GET {base}/videos/{upstream_id}` |
| 内容 | `GET {base}/videos/{upstream_id}/content` |
| 型号发现 | `GET {base}/models`，OpenAI 风格 data[].id |
| 取消 | 可选能力；BBLabu 当前不支持，不凭状态名推断端点 |

Base URL 统一处理域名和尾部 `/v1`，禁止产生重复 `/v1/v1`。不得把接入协议相同理解成免费生成、支持取消或返回相同计费 usage。

管理端账号表单提供：账号名称、供应商显示名称、协议、Base URL、API Key、模型同步/选择、模型采购价。账号名称和 URL 已存在；供应商显示名可用新的非敏感 extra 字段保存，无需新建供应商管理子系统。新协议必须显式填写 URL，不默认发送到 BBLabu。

内部现有 `platform=seedance` 调度/分组命名首期保留，相关用户界面可显示“视频任务”；不为改展示名进行全库平台迁移。新旧协议共用必要的请求与解析内核，`bblabu_v1` / `fflink_v1` 的保存值、旧分组及旧任务继续可读。旧账号不因升级自动扩大授权或改变价格。

## 3. 模型发现与能力目录

管理员点击同步：读取该账号 `/models` → 展示发现结果 → 匹配能力目录 → 手动选择并保存。同步失败保留原选择与能力；不覆盖手工价格，不自动上架，不通过生成请求探测。

发现列表区分“已配置可用”“缺能力配置”“缺销售价/采购价”“账号未授权”。已发现的新型号可新增能力条目；能力未确认时拒绝执行，不能绕过校验原样透传。

BBLabu 内置完整 33 型号能力模板，依据 `video-catalog=2026-10-16.1` 及三个官方型号文档；精确型号见 [审计清单](D:/Code/Other/sub2api/docs/BBLABU_MEDIA_COMPATIBILITY_AUDIT.md)。目录只作为能力模板，价格须换算并由管理员保存；公开 `/api/video-catalog` 不是所有同协议供应商都必须实现的接口。

公开资料有一处需单列：mm3 的提示要求每段参考视频提供时长，但页面生成的通用参数表仍写 string[]，没有给出时长的正式传输结构。将此参考视频组合标记待核验；只有核实正式 schema/真实响应后才能启用，不能凭猜测生成夹具或宣称该组合已完整兼容。型号存在与所有模式已验证是两个状态，不影响先完成其他确定能力。

目录记录公开模型 ID、精确上游 ID、请求字段 profile、默认值、时长/分辨率/比例、参考图/视频/音频数量、首尾帧组合、音频开关、支持操作、计费单位与参考输入计费策略。能力有版本号，任务提交后冻结适用版本。

保留既有 Seedance 别名；其他线路按完整型号精确匹配，保留 `sd13-`、`gv3-` 等前缀。禁止用 Grok 家族模糊匹配借价。同名但能力不同的供应端须按账号覆盖能力；对外暴露可路由账号的兼容能力，不能随机选择不支持所提交参数的账号。

## 4. 请求字段与参数校验

同一供应商内可以包含两个固定 profile，由每个模型的能力记录选择：

| 语义 | camel_refs（BBLabu 官方型号） | snake_refs（BBLabu 线路） |
| --- | --- | --- |
| 比例 | ratio | aspect_ratio |
| 参考图片 | referenceImages | reference_image_urls |
| 参考视频 | referenceVideos | reference_videos |
| 参考音频 | referenceAudios | reference_audios |
| 首/尾帧 | first_image / last_image | first_image_url / last_image_url |

对外沿用现有 Sub2API JSON 字段，适配器负责转换。按模型决定是否发送 duration/resolution/generate_audio，固定规格型号不补发不支持的字段；例如 Omni 不应强制收到时长、分辨率或音频开关。

补齐整数时长、比例、分辨率、素材 HTTPS、素材数、尾帧必须有首帧、首尾帧与参考素材组合、音频及 n 校验。每个视频任务只允许 n 省略或 1，批量由多个独立任务组成。新增 768p、2k 等目录规格，不能借用其他分辨率价格。

对需要逐段参考时长的型号（如 mm3）增加受控素材元数据：公共 referenceVideos 兼容 URL 字符串，并可接收 `{url,duration_seconds}`。独立平台从素材元数据构建对象，适配器按上游已核实的请求 schema 编码；不能推测上游对象字段名。该时长用于素材约束，不替代最终计费量。

新协议不克隆任意 Raw 字段向上游转发；仅构建已定义字段。旧客户端已有别名继续按原语义兼容。供应商返回未知状态保持非终态并记录诊断，不猜测成功。

## 5. 销售价与采购价

| 模式 | 冻结/最终计算 | 规则 |
| --- | --- | --- |
| video（按秒） | 规格单价 × 计费秒数 × 已有适用倍率 | 输出秒数，可按模型额外计算参考视频输入秒数 |
| per_request（界面显示按条） | 规格每条价 × 1 × 已有适用倍率 | 一个成功视频任务一条；查询/下载不重复收费 |

两种模式都允许按模型实际支持的分辨率配置；固定规格型号使用默认每条价。销售模式与账号采购模式独立，允许“采购按条、销售按秒”等组合，不从一方推断另一方单位。沿用既有分组售价倍率与账号成本规则，不擅自改变旧倍率语义。

按秒销售必须配置明确的 quantity_policy：按合同约定的请求/固定输出秒数，或按可信服务端实际输出秒数；同时具备输出及参考输入的预占上限。按实际输出时，只有正数可信计量才能结算，最终量超过预占上限进入异常处理，不能静默超扣。像 Omni 仅描述“约 10 秒”的型号默认只能按条售卖，不能用估计时长、0 秒或无上限预占开启按秒销售；采购按秒同样须满足可信计量条件。

账号采购端已有 per_request，但当前 Seedance 禁止其按分辨率分档，必须补齐；用户销售端当前只有 USD/秒，需要新增模式。不得把 `*_per_second` 列改作每条价。

销售配置采用显式新版版本标识；旧历史渠道中的 token/image/per_request 行原先不参与视频销售，升级后继续不参与，只有管理员在新表单明确保存后才启用新版按条价。缺价拒绝提交，不能用相近型号、分辨率或默认 Grok 家族价兜底。

任务在发送上游前冻结销售模式、单位价、单位、报价版本、规格、倍率、参考输入计费策略及账号采购快照。持久表新增可空的销售快照 JSONB；无新快照的旧任务仍走旧按秒结算。账号成本快照沿用并扩展必要的规格信息。

按条销售不依赖参考视频秒数计算固定零售价；但若采购按秒仍需要参考计量，继续按现有事务边界保持 settling，计量齐备后一次结算。销售金额始终为冻结的固定价，不重复结算、不为固定单价任务强行套入无关秒数。

参考视频的实际秒数必须来自可信服务端结果；精度与舍入按供应商正式规则实现并测试，不截断小数或信任调用方自报。上游未给可信字段的组合在正式售卖前需验证或禁用该计费组合。

所需输出/参考计量长期缺失时进入有处理时限的异常队列，由管理员按账单核查、释放/退款政策决议；保留原任务记录与决议审计，不无限保持 settling，也不通过重新生成补计量。

旧 `video_model_prices` 含义是每秒价，仅继续投影按秒条目；新增带 billing_mode/unit 的媒体能力价格输出供新平台读取。管理员价格表和成本表明确显示 USD/秒或 USD/条，BBLabu 平台刀须换算，禁止直接照填美元。

## 6. 跨供应商任务 ID 与兼容

当前 `(user_id, api_key_id, provider_task_id)` 唯一，两个供应商返回相同任务号会在受理后绑定冲突；只放宽索引又会产生查询歧义。

新任务复用唯一 `state_id` 作为公开 ID，创建前生成 `vid_` 加 16 字节安全随机数的 hex 编码，随机源失败则拒绝创建；不能复用当前进程前缀加序号的生成器。`provider_task_id` 独立保存上游编号。状态、内容、取消、usage 关联及计费幂等都使用统一 helper 生成公开身份；driver 始终使用原上游编号。

查询先按公开 state_id + user + Key 查新任务；未命中只对明确的 legacy 行回退旧上游 ID。新任务不接受裸上游 ID 作为第二个查询别名。旧任务的公开 ID、usage response ID、StableBillingID 保持原值，避免历史结算去重标识变化。

新增迁移显式区分新旧 ID 版本；为新任务建立包含账号和协议的上游编号唯一约束，旧任务保留原 owner/Key/task 的局部唯一约束，再替换原全表索引。新旧 claim、更新、恢复均定位已鉴权本地行，不按裸上游 ID 跨供应商修改。

冻结原账号、协议、上游型号、Base URL、字段 profile 及内容能力，后续查询不漂移到另一供应商。持久快照不含明文 Key；凭证通过原账号引用读取。在途任务不得删除原凭证，Key 轮换须保留取回能力。

新增迁移同时放宽新协议允许未知 duration 的约束，并同步 repository/快照校验，旧任务规则不变。先部署所有实例兼容读写，再启用新协议创建；旧版本 recovery 不能领取新快照任务。回滚前停用新创建并排空新任务，不能让旧结算器处理每条价或未知规格任务。

## 7. 错误、恢复与对外目录

沿用当前 8 字段视频成功响应与 5 个公开状态；供应商细节不泄漏给下游。固定型号的 resolution 可为空字符串、未知时长用 0，类型不变；不得伪造为 480p/4 秒，并通过能力目录说明不可调节字段。旧 Seedance 默认值不变。

新增 `GET /v1/media/models`（提案，尚未实现），使用现有 Bearer 鉴权和按 Key/分组过滤，返回 data[]、能力版本、公开型号、允许参数、操作能力及带单位的销售价格；不返回供应商、采购成本、密钥、内部账号。现有 `/v1/models` 的列表 schema 保持原样。

创建结果未知时不得盲目重试或换账号再次生成。网关与平台各自记录 attempt 和待核查状态；上游无幂等保证时不能宣称跨系统恰好一次。现有未提供的创建幂等/任务找回不冒充已实现，本次先保证明确已受理任务的恢复与去重，未知提交进入受控异常处理。

## 8. 实施单元与验收

1. 能力目录及严格请求构建：33 个模板、两个 profile、账号模型同步、未知型号待配置；fflink 原能力隔离。
2. 计费与迁移：新版按条售价、按条采购分辨率档位、快照、旧配置不变、旧投影不混单位。
3. 任务身份：网关 ID、双路径旧任务查询、跨账号重复上游 ID、统一结算身份与恢复。
4. 管理端：协议和供应商表单、模型同步与状态、能力表单、明确价格单位，中英文完整。
5. 对外契约与图片准入：新增能力目录、保持视频 JSON，准确放行当前 9 图片型号并复用标准转发；不把准入测试写成真实生成成功。

验收覆盖：全部 33 型号的请求/状态/content 夹具；素材组合；768p/2k；按条/按秒交叉售采；分档缺价；重复轮询只计一次；两供应商同编号；Key/用户隔离；旧任务和旧价格兼容；供应商换 URL 后在途任务取原端；断网/进程恢复；接口新增错误结构与权限测试。

后端实现后按 AGENTS 执行 gofmt、`go test ./...`、`go test -tags=unit ./...`、golangci-lint；管理端执行 typecheck、test:run、build，嵌入资源测试及 API 契约测试。发布前 Docker 集成测试与受控真实生成验收另行记录，不以自动跳过或 mock 代替。

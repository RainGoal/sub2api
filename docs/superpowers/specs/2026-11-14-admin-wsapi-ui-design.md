# Sub2API 管理端统一为 wsapi UI 风格

日期：2026-11-14。状态：用户已确认视觉方向；本文记录实施边界与验收要求。

## 目标与已确认方向

让 Sub2API 管理端沿用 wsapi 用户端的 UI 风格：石墨灰暗色表面、余烬橙强调色、
克制的边框与圆角、紧凑排版、清晰的数据层级。管理端保留现有导航、功能、字段、
权限、业务交互和 API。目标覆盖整个管理工作区，不以仅更换主色或改完概览页为完成。

用户已确认“统一视觉语言，保留各自信息架构”，并确认并排样稿方向。
样稿只表达视觉规则；示例名称、数据、导航、按钮和示意图标不作为功能变更要求。
站点名称、Logo 和自定义菜单继续取现有配置，不硬编码为样稿中的 Sub2API 或 Yusflow。

视觉依据为 `D:/Code/Other/wsapi-front/src/styles/main.css` 的公共规则和暗色变量，
壳层参考同仓库 `src/layouts/AppShell.vue`，字体依据 `src/main.ts`。
本地已确认样稿位于 `.superpowers/brainstorm/wsapi-admin-style/visual-style.html`；
该文件属于忽略的讨论材料，本文包含可独立实施的规范，不依赖预览服务存活。

## 实现路径选择

| 路径 | 效果与代价 | 决策 |
| --- | --- | --- |
| 独立品牌层、适配公共组件、逐页收口 | 保留上游业务结构，覆盖真实差异，可分批验证 | 采用 |
| 只换 Tailwind 主色 | 改动少，但渐变、大圆角、统计卡片和图表仍不一致 | 不满足目标 |
| 复制 wsapi 页面或重建管理前端 | 增加业务重复和上游合并成本，超出视觉统一范围 | 不采用 |

## 页面范围与主题边界

- 管理工作区：以现有路由 `meta.requiresAdmin === true` 为准，覆盖概览、用户、
  账号、分组、渠道、监控、审计、用量、订单、设置以及其他已注册管理页面。
- 后台入口：已有 `backend_mode_enabled` 开启时，`/login` 同步采用品牌外观；
  只改变登录页的视觉与 AuthLayout 表面，不改变登录协议、OAuth、验证码或跳转。
- 普通用户内嵌页、管理员访问的个人页和公开页保持既有主题行为；不按用户角色给全站换肤。
  `backend_mode_enabled` 未开启的共用登录页不在本轮换肤范围。
- wsapi 仓库不改动；不引入跨仓源码、构建产物、运行时依赖或共享业务组件包。
- 不新增后端开关、接口、数据库迁移；不改权限、支付、计费、网关及菜单功能开关。

成功、警告、错误和信息保留绿、黄、红、蓝语义；模型平台品牌图标与类别标识保留辨识度。
移除后台装饰性渐变、光晕、玻璃卡片、悬浮位移和彩色大块统计图标底。
品牌橙不能替代错误红、成功绿，也不能覆盖已配置 Logo 或第三方支付标识。

## 品牌层与最小挂载

建议在 `frontend/src/brand/` 新增本地 tokens、管理端样式和小型主题适配模块。
变量使用品牌前缀；主题颜色和控件尺寸集中定义，不把 wsapi 整份 CSS 直接引入。
本地字体通过 wsapi 已使用的 Fontsource 包按所需字重打包，锁定依赖并保留字体许可；
不引用另一个仓库的 node_modules 或联网字体 CDN，验证字体包体积及加载失败时的回退。

在 `main.ts` 导入样式，在 `App.vue` 增加独立的主题作用域同步，首次路由完成后、
子页面和图表创建前应用 `html[data-admin-brand="wsapi"]` 与现有 `.dark` 类。
管理路由依据路由元数据判断；后台登录依据既有公开配置和 `/login` 判断。
监听路由及公开配置变化，离开生效范围时移除品牌属性，按原有 localStorage / 系统
偏好恢复 `.dark`；品牌强制暗色不写入原有 `theme` 偏好。
配置尚未到达时遵循既有配置加载流程，收到配置后同步外观，不额外发起业务请求。

当前 `main.ts` 和 `AppSidebar.vue` 都有主题初始化，侧栏仍提供浅色切换。
需让侧栏在品牌范围内遵循强制暗色并隐藏切换入口，避免它覆盖根部设置；其他范围保持原行为。
直接打开管理深链接、登出重定向、浏览器前进后退和普通页往返均属于主题生命周期验收。
不为样式判断增加或绕过路由权限判断，既有鉴权结果仍决定页面是否可访问。

品牌作用域挂在 html 而非仅 AppLayout，确保 Teleport 到 body 的下拉框、弹窗、提示、
公告和通知一起使用新外观。复用现有组件的 props、slots、events、键盘和焦点管理。
优先适配 `.btn`、`.input`、`.card`、`.modal-*` 等语义类；有内联工具类的结构添加
少量稳定挂载类。不使用 `[class*="rounded"]` 等宽泛匹配，不用全局 `!important`
强压样式，不把整套 Tailwind 配色全局改为 wsapi 配色。

## 外壳、组件与页面

- 外壳：`AppLayout.vue`、`AppSidebar.vue`、`AppHeader.vue` 在品牌范围内使用相同
  石墨底色与 1px 分隔线。侧栏目标宽度 232px、收起 68px，顶栏 56px，桌面左右留白
  24px；侧栏宽度与主区偏移一起调整。保留菜单分组、折叠、权限开关、当前选中、
  自定义菜单和窄屏抽屉；不复制用户端的移动底部导航。顶栏原有动作继续可达。
- 表格壳：`TablePageLayout.vue` 现有高度写死为 `100vh - 64px - 4rem`，必须随
  顶栏与留白同步调整；保留固定表头、固定操作列、分页、底部横向滚动和移动卡片模式。
- 公共组件：覆盖 DataTable、Pagination、Input、SearchInput、Select、TextArea、
  Toggle、StatusBadge、StatCard、Skeleton、EmptyState、BaseDialog、ConfirmDialog、
  Toast、HelpTooltip、DateRangePicker，以及公告和管理员合规弹窗的外观。
  不重写选择、排序、过滤、焦点圈定、滚动锁、禁用或提交防重逻辑。
- 概览：`views/admin/DashboardView.vue` 含多组直接编写的统计卡片，需要单独适配。
  数值突出、标签弱化、装饰图标中性化；保留全部既有指标、分组、单位和筛选。
- 图表：CSS 不能改 canvas 内绘制的硬编码色。给后台概览、用量、账号统计、支付统计、
  ops 图表增加小型品牌颜色读取适配；品牌范围外返回原有颜色。背景、网格、图例、
  提示框一起适配，主序列采用 wsapi 橙色，多序列保留可区分的类别色及正确图例。
  不修改数据、统计口径或图表依赖版本。
- 页面收口：检查所有已注册管理路由，处理局部写死的蓝灰底色、渐变、圆角和间距。
  只有仍不符合规范的节点需要改动；不是要求把全部模板重写一遍。

## 实施顺序与完成定义

1. 品牌 tokens、字体、主题边界、外壳和浮层公共样式，建立最小完整基础。
2. 完整适配概览及用户 / 账号 / 分组 / 渠道列表，验证数据、表单、表格和弹窗组合。
3. 收口其余管理页、ops / 用量 / 支付图表、后台登录外观，完成全路由巡检。
4. 执行全量前端检查、构建和内嵌资源验证，提交视觉对照及功能回归结果。

这些是同一改造的实施批次；前两批不能作为“整个后台统一完成”的交付。
每批按最小修改原则进行，不趁机重构业务 service、拆分业务大文件或调整路由命名。

## 状态与交互验收

- 对比 wsapi 暗色实际页面与管理端真实页面，不以讨论样稿的缩小字号或模拟数据代替验收。
  桌面检查 1440px、1024px，窄屏检查 390px；中英文、长标签和 200% 缩放下操作可达。
- 重点页面：概览、用户、账号、分组、渠道定价 / 监控、用量、请求审计、订单、设置、
  ops 和后台登录；其余管理路由逐页检查并记录。隐藏在功能开关后的页面也要用本地
  测试数据覆盖，不为验收改动生产开关。
- 加载中、空数据、失败重试、禁止访问、禁用、重复提交和选中状态保持可辨识。
  保留既有错误文本及交互；新文案或新增可访问名称同步补齐中英文。
- 表格检查搜索、筛选、排序、分页、批量选择、列显隐、长字段、固定列和移动卡片。
  现有功能按所在页面检查，不新增原本没有的表格能力。
- 浮层检查 body Teleport 的 Select、提示、日期筛选、通知、确认框和多层弹窗；
  键盘焦点、Esc、滚动锁、遮挡层级和弹窗关闭后的焦点恢复不得退化。
- 浅色偏好下直接打开管理深链接应在内容呈现前进入暗色；管理页之间切换保持样式。
  离开管理范围、登出、返回普通用户或公开页恢复原偏好；不遗留品牌属性。
- 多系列图表和状态提示不得只依靠颜色表达含义；正文对比度至少 4.5:1，
  焦点及必要控件边界保持可识别，减少动效偏好生效。

## 部署、回退与已知风险

- 前端实际构建输出是 `backend/internal/web/dist`（来自 `frontend/vite.config.ts`）。
  发布需要把新静态资源打进应用镜像；不提交该目录或 `frontend/dist` 的构建产物。
- 本方案无数据迁移，管理路由不依赖新增后端开关；后台登录换肤使用既有
  `backend_mode_enabled`，不为了视觉改造调整它的线上值。
- 部署遵循仓库的 compose 备份、配置检查和应用容器替换流程；核对 `/login`、
  `/admin/dashboard`、列表深链接刷新、静态资源、字体资源、健康接口和容器日志。
  OAuth 与支付回调保持原路由；检查相关入口与回调页的兼容性，避免全局样式回归。
- 如需回退，切回前一应用镜像并按现有流程重建应用容器；不操作数据卷。
- 主要风险是共享组件样式泄漏、局部工具类覆盖优先级、canvas 配色遗漏和紧凑布局溢出。
  通过根作用域、稳定语义类、全路由巡检和实际截图控制；上游同步后复核被改动的挂载点。
- 字体资源可能增加构建体积；记录新增资源大小，优先所需字重并验证缓存、回退与可读性。

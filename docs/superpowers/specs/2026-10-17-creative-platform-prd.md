# 独立图片 / 视频创作平台 PRD

日期：2026-10-17。状态：首发需求设计稿，未实现。以用户最新范围覆盖早期团队化建议。

## 1. 产品与明确边界

面向专业设计和视频创作，核心是项目、无限画布、分镜、素材与生成任务。首发为单账号、单钱包；用户可共用该账号登录、使用同一积分余额。项目、任务、素材、订单归账号，不建立团队组织。

独立用户库、会话、钱包与充值订单；支持易支付。浏览器只调用新平台 API，后端只通过固定 Sub2API 连接器生成图片/视频，不向用户提供供应商 Key、任意 Base URL 或原始网关转发。

**首发不做**：成员邀请、工作空间、角色/预算、付款人拆分、实时多人协同、整图自动执行、自动编剧、完整视频剪辑/合片/转码、社区、分销、订阅及对外售卖 API。

## 2. 主流程与页面

主流程：新建项目 → 上传/整理参考素材 → 手动建立分镜 → 生成图片候选 → 选图与参考修改 → 生成视频候选 → 选定交付版本 → 下载。

| 页面 / 视图 | 首发需求 |
| --- | --- |
| 登录与账户 | 邮箱注册、验证、登录、找回密码、退出、修改密码、会话撤销；允许多设备会话 |
| 项目首页 | 新建、重命名、搜索、封面、最近编辑、归档与恢复 |
| 项目画布 | 文本、素材和生成节点；缩放拖拽、多选分组、连线、撤销重做、预览、候选对比 |
| 项目分镜 | 手动新建和排序镜头卡片；镜号、描述、提示词、目标比例/时长、参考素材、图片/视频候选、选定结果 |
| 项目素材 | 上传、类型筛选、预览、引用位置、下载；区分上传文件和生成结果 |
| 任务中心 | 项目/媒体/状态筛选、输入快照、报价、扣费、进度和异常处理状态 |
| 充值与积分 | 可用/冻结积分、充值商品、订单状态、消费/释放/退款流水 |
| 基础管理后台 | 用户状态、模型商品和零售价、充值查单/补单、任务异常、积分调整、存储和审计 |

快捷生成放在项目侧栏或素材操作中，与画布共用任务服务；结果可以插入画布和分镜，不维护第二套生成逻辑。项目首页及编辑入口优先适配桌面；窄屏至少可查任务、预览、下载和充值，不承诺手机具备完整桌面画布效率。

专业风格沿用深色工作台、紧凑参数和大预览，可借鉴参考站交互；不复制其品牌、示例素材或未接入的模型能力。

## 3. 画布与分镜行为

画布云端自动保存，明确显示保存中/已保存/失败。保存使用版本号；同账号两个设备写入旧版本时返回冲突，保留本地草稿并提供重载或另存副本，不静默覆盖。不引入 CRDT 或共同光标。

连线表示输入引用和创作来源。单个节点显式点击生成才提交任务，并先显示服务端报价；复制、移动、连线、撤销或删除节点均不自动生成、扣积分、取消或退款。

重生成创建新任务和候选，保留旧结果。提示词或参考素材修改只影响后续提交，不能改写历史任务快照。分镜的选定图片/视频独立于候选列表，重新生成不自动覆盖已选交付版本。

分镜是项目内容组织方式，首期不提供自动整片生成或剪辑时间线。下载单个成品与选中成品包；打包失败可重试下载，不重新生成或再次计费。

## 4. 数据关系与存储

账号拥有项目、积分钱包和充值订单；项目拥有画布、分镜、任务与素材引用。画布/分镜只保存 task_id、asset_id 和布局/选定关系；任务保存执行与计费事实。

核心实体：users、sessions/验证记录、projects、canvases（含 graph_schema_version/revision）、shots、generation_tasks、task_attempts、assets、model_products、quotes、wallet_accounts、wallet_ledger、payment_orders、admin_audit。可按现有技术实现合并辅助表，不为未来组织功能预留完整体系。

任务不可变快照包含账号、项目、提示词、模型、规格、参考素材 ID、价格版本、零售金额、请求去重键、上游任务 ID 与原服务 Key 引用。媒体保存对象存储 key、格式、大小、像素尺寸/时长和来源任务；同一文件多处引用不重复复制。

素材验证实际类型、大小与媒体元数据，采用私有对象存储和短期下载签名；提交上游前产生足够有效期的 HTTPS 素材 URL。删除有引用或在途任务依赖的素材时阻止立即物理清理，提供解除引用/延迟清理说明。

项目归档不取消任务、删除作品或退款；删除项目须显示影响与二次确认。在途任务保留可查询记录和所需素材。保存期限、容量和清理规则由后台配置并展示给用户，上线前必须明确，不把临时供应商 URL 当永久作品。

## 5. 模型商品与报价

Sub2API 提供能力，创作平台维护可售商品和积分价格；新发现型号不会自动上架。上架条件为能力已配置、服务 Key 有权使用、网关价格完整、受控真实生成/下载验证通过。

参数面板按商品能力显示时长、分辨率、比例、音频、参考素材和首尾帧；不提供任意模型名、任意参数 JSON 或脚本。后台和服务端同时校验，不能只限制界面。

每次报价绑定模型、参数、素材、价格版本和有效期。修改影响价格的输入后重新报价；提交显示本次固定积分，服务端校验后冻结。参考视频额外成本通过报价或明确的素材上限覆盖，不能事后因采购价变化追扣。

视频一任务一条；图片首发默认一次一张。多候选以多个明确报价的独立任务实现，逐个成功/失败结算，避免未定义的批次部分成功收费。

## 6. 积分与任务账务

人民币以整数分、积分以整数最小单位存储；PostgreSQL 事务和不可变流水是财务事实，Redis 只作限流和任务唤醒。积分兑换、商品价格与规则均保存版本快照。

| 动作 | 钱包变化 |
| --- | --- |
| 充值成功入账 | 可用积分增加 |
| 提交生成 | 可用减少，冻结增加 |
| 成功生成并归档交付 | 冻结转已消费 |
| 明确失败 | 冻结释放回可用 |
| 已消费后退款 | 新增反向流水，返还原账号钱包，不修改历史流水 |

本地提交采用 `(account_id, request_key)` 唯一与参数摘要，同键同内容返回原任务，内容不同为冲突。多设备并发共享同一钱包，余额检查与冻结在事务中完成；重复回调、重复 Worker、重复轮询不得重复记账。

生成状态、媒体交付状态、零售结算状态与采购对账状态分开记录。用户充值只进入本平台；Sub2API 服务账户采购余额由运营另补，不共享数据库、不自动同步余额、不为每个用户建影子网关账号。

| 异常 | 首发处理 |
| --- | --- |
| 参数/余额检查失败 | 不发上游，不消费 |
| 明确未受理或终态失败 | 幂等释放；已结算情况按公布政策退积分 |
| 已发送创建但没拿到 ID | 提交待确认，不自动重发；后台核查并在配置的处理期限内决议 |
| 有 ID 后超时/断网/暂时 404 | 继续核查原任务，不重新生成 |
| 已生成、归档失败 | 只重试取回和存储；显示保存重试，不重新生成 |
| 页面关闭/重新登录 | 服务端继续任务，可恢复查询 |
| 不支持取消/取消未确认 | 不释放冻结；明确提示任务继续 |
| 已退款后迟到完成 | 不再次扣积分，按公布的交付政策处理 |

平台首发采用固定规格报价并承担采购波动；不能用网关 Key 汇总余额变化伪造单任务采购账单。后台按上游任务关联使用记录核对成本；精确自动采购账单查询不是当前已有能力。

## 7. 易支付充值

用户选充值商品 → 服务端创建唯一订单，固定人民币/积分快照 → 商户收银台 → 后端验签通知或主动查单 → 核对商户、订单、金额、成功状态 → 同一事务入账一次。

客户端不决定金额。新平台使用独立订单前缀、库和 notify/return 地址；支付返回页只查订单，不凭 URL 参数发积分。支付状态与积分到账状态分开，允许显示“支付成功，到账处理中”。

重复通知与查单并发由订单唯一入账流水保护。数据库暂时失败不回复已入账成功；通知丢失用查单补偿。过期订单收到晚到成功通知仍须核单，不直接丢弃；网络错误不是未付款。

实际签名算法、支付方式、查单参数、回调应答以所用易支付商户文档与小额联调为准，不假设所有“易支付”版本完全一致。任务退款首发退积分；充值原路退款由后台人工处理，不承诺未验证的自动退款端点。

## 8. 技术基座与独立业务 API

推荐独立仓库：固定 infinite-canvas 前端版本，沿用 React/TypeScript；新 Go API + Worker、PostgreSQL、Redis、私有 S3/R2。首期单体应用加后台 Worker，不引入微服务。Sub2API 管理端继续 Vue，不改造成创作前端。

infinite-canvas 复用画布交互；替换浏览器直连模型、Key/Base URL 配置、本地媒体/项目保存和供应商任务轮询。去掉动态模型脚本、远程插件与本地 Agent 入口，前端只保留审核后的节点及平台业务 API。

新平台接口采用自己的 `/api/v1` 与登录会话：auth/me、projects、project canvases/shots、assets、model-products、quotes、tasks、wallet/ledger、payment/orders。每个读取、更新和下载均服务端校验账号归属。画布保存携 revision，冲突返回 409；任务提交携 quote_id/request_key，价格由服务端决定。

接口成功体统一为平台自己的业务包装；401 未登录、404 不存在或非本人、409 幂等/版本冲突、422 参数错误、429 限流。异步任务详情提供稳定业务状态，不直接转发网关错误体。后台操作走同一业务服务，调账、补单、退款须留原因和审计。

## 9. 开发顺序与发布验收

1. 先完成网关通用视频能力与对外契约；图片准入同步补齐，以真实可用商品作为前端目录。
2. 独立登录、项目/云端画布、私有素材、任务 Worker，跑通“参考图 → 生图 → 视频 → 自有存储”。
3. 接入积分钱包与易支付；验证事务、并发、回调/查单补偿和故障恢复，再开放收费。
4. 完善分镜、候选对比、选定版本、任务中心和基础运营后台，完成端到端验收。

验收：账号隔离；共用账号的多设备余额并发安全；重复提交不重扣；画布冲突不覆盖；节点删除/撤销不退款；刷新/重启恢复已知任务；响应丢失不重发；归档失败可恢复；支付重复/丢失通知补偿；模型参数与零售价一致；结果可下载；中英文及加载/空/错/余额不足状态完整。

上线配置必须包含品牌/域名、充值商品和兑换率、首发模型价格、易支付商户/回调、服务 Key、存储与保留规则、未知提交处理期限及退款政策。它们是运营配置，不引入额外业务子系统。

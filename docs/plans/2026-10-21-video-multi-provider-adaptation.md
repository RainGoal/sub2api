# 视频多供应商接入与志奇适配计划

## 目标

同一视频分组可同时配置 BBLabu JSON v1、志奇及既有视频供应商。客户继续使用现有 `/v1/videos` 创建、查询、下载入口、公共任务 ID、参数和响应格式。新增供应商不能改变其他供应商的协议、计费口径或已提交任务的执行方式。

## 业务边界

- 供应商协议由账号的 `video_provider` 显式选择，志奇使用独立 `zhiqi_v1` 适配器。旧协议保持独立。
- 公共模型名可显式映射到不同供应商型号；省略映射时保留原名对应原名的行为。模型发现只提供候选，不自动授权模型，也不自动配置价格或可信计量。
- 调度以完整请求能力为准，不能换号后丢弃素材、改分辨率、改时长或隐式替换公共模型。
- 请求默认值不得随账号顺序变化：可用候选的缺省时长、分辨率或比例冲突时，要求客户端显式填写对应参数；只有一个候选或候选默认一致时保留默认行为。
- 创建前校验账号能力与采购、销售计量条件；选择账号后再次校验完整参数及冻结销售合同。预占额度覆盖可用候选的最大必要额度，不拼接虚构能力。
- 提交结果不确定时保留原任务与额度，不自动换供应商重新生成。
- 提交成功后冻结供应商、地址、上游模型、能力和价格。查询、下载、恢复与结算使用原任务快照，账号编辑不迁移旧任务。
- 按次、请求合同秒数、实际秒数沿用现有语义；缺失实际计量时不能自动替换为请求时长。旧 BBLabu 无计量任务的人工恢复不在本次范围。

## 适配范围

1. 注册独立志奇协议，复用 Bearer 鉴权及 `/videos`、`/videos/{id}`、`/videos/{id}/content` 路径。
2. 将公共参考素材、首尾帧、比例、时长等参数转换成志奇字段；原 BBLabu 编码器保持原行为。
3. 解析志奇的 `usage.duration_seconds`，保留小数精度。`usage` 缺省时按既有结算合同处理，不伪造计量。
4. 将上游 `expired` 识别为失败终态，按既有公共失败格式返回并释放未结算额度。
5. 兼容志奇内容接口的视频字节和 JSON 下载地址形式，沿用受控媒体获取链路，不向客户端泄露凭据。
6. 将能力校验、发现、目录与账号重校验的公共挂点从单个 JSON v1 判断扩展为明确的协议能力判断。
7. 管理端新增志奇选择、相应字段配置与中英文说明；不新增用户端仓库依赖。

## 验收条件

| 维度 | 必须通过 |
| --- | --- |
| 现有兼容 | BBLabu、FFLink 既有测试及请求/响应合同保持通过 |
| 同组混合 | JSON v1 与志奇使用同一客户请求，分别发送正确上游字段和型号，公共响应结构一致 |
| 能力调度 | 不支持完整素材、时长、分辨率组合的账号不能发起上游请求；换号后复核仍生效 |
| 默认稳定 | 调换账号顺序不改变请求默认值或预占额度；默认冲突必须明确拒绝，显式输入仍可调度 |
| 执行冻结 | 修改当前账号协议、地址、型号映射、能力后，已提交任务仍查询原供应商与任务 ID |
| 计费稳定 | 销售与采购独立计量，小数秒不截断；首次成功计量冻结后重试保持金额和幂等标识 |
| 错误与下载 | expired、缺失计量、JSON 下载地址、视频字节、未知提交结果和取消不支持均有明确行为 |
| 管理配置 | 志奇模型来自发现或显式配置；不写死志奇型号，不自动启用模型；中英文文案齐全 |

## 已实施的接入方式

1. 在视频账号中选择 `Zhiqi V1`，填写该供应商 API Key；默认地址为 `https://zhiqiapi.com/v1`，也可填写其实际 API 前缀。
2. 发现上游型号，依据该型号文档配置能力并显式勾选。志奇没有内置型号列表；发现结果不会自动开放模型或填入价格。
3. 对外可使用稳定公共名称，例如 `studio-video`；在能力中填写对应 `upstream_model`，不同账号可把同一公共名映射到各自上游型号。采购成本与渠道销售价格均按公共名配置。
4. 同一公共名称的缺省时长、分辨率、比例应保持一致。确需不同默认值时，客户应显式提交这些参数；网关拒绝含糊请求，避免账号顺序或换号改变生成内容。
5. 按实际秒计价前，应确认该型号完成响应确实包含有效 `usage.duration_seconds`，再开启可信计量。志奇只提供输出秒数，带参考视频的请求不能使用“输出＋参考实际秒”合同；网关在提交前筛除此类账号，公开目录也不展示该组合的参考视频能力。

现有客户继续调用 `/v1/videos`、`/v1/videos/{id}` 和 `/v1/videos/{id}/content`，使用公共任务 ID，无需知道本次调度到哪家供应商。后台复用原视频任务开关 `GATEWAY_VIDEO_TASKS_JSON_V1_ENABLED`，未新增独立环境开关；现有显式关闭配置仍生效，已有任务按原快照处理。

志奇查询的 `expired` 转换为失败终态；未公开取消协议，管理端和后端都拒绝启用取消能力。内容接口返回 JSON 地址时，网关逐跳检查公共 HTTPS 目的地、遵守出站白名单，并保留 Range 下载语义；CDN 下载不携带供应商密钥或账号自定义请求头。开启出站白名单的部署须包含实际视频 CDN 主机。

官方文档说明，`media_storage_failed` / `media_storage_unavailable` 可能发生在上游已生成而平台交付失败之后，且不退已经发生的上游费用。本轮沿用现有失败任务的客户退款语义，未新增采购损失账务；实盘联调需单独核对供应商账单。文档来源：[视频生成](https://zhiqiapi.com/docs/api/video-generation)、[视频接口](https://zhiqiapi.com/docs/api/video)。

## 兼容性复查修复（2026-10-22）

- 旧 BBLabu/FFLink 候选也参与混组默认值校验。若其默认 4 秒、480p、16:9 与志奇等有效候选不同，请求会在预占和上游提交前返回 422，要求明确时长、分辨率和比例。参数不受支持或对应销售、采购分辨率价格缺失的旧候选不制造默认冲突；仅旧协议分组仍保留历史默认行为。混组价格校验按公共模型名匹配，避免旧解析器的别名规范化漏掉精确配置。
- 旧协议参数预检补齐构建请求所需的 API Key，修复兼容账号被本地误排除的问题。预检只构建并关闭请求体，不访问上游。
- 能力查询依次采用显式公共名配置、显式映射目标配置、内置预设；显式禁用不会回退到预设。修复 `grok-imagine-video → Supplier/PrivateRoute` 等公共名碰巧命中其他供应商预设后，志奇能力被遮蔽的问题。
- 创建请求收到明确的 401、403、429 拒绝时，可以选择另一个兼容账号；请求参数等其他 4xx 仍停止。408、5xx、网络错误、成功响应缺少 ID 继续按未知提交处理，不换号重发。全部账号明确拒绝时释放一次额度；换号后提交结果未知时，保留实际提交账号的快照、原公共 ID 和预占额度，进入待审。
- 使用公共任务 ID 的新任务按冻结的公共模型名响应，创建及查询切到旧协议也不再改变公共名大小写。新协议候选暂时不可用、只剩旧账号时，仍按版本化价格的公共名匹配，不再因规范化误报销售价缺失；旧版价格保留原规范名和默认值。历史任务的原响应规则保留。

回归覆盖：两个旧协议、两种账号顺序、三个默认参数冲突、显式参数、默认一致、不可用价格/能力候选、志奇切换到同协议及三种其他协议、全部拒绝、换号后未知提交、公共模型名与执行快照保持一致，以及只剩旧账号时的新旧价格合同。

统一 API 继续使用本项目已有字段语义，并非志奇原生字段的完整透传。独立的主参考素材 `input_reference` 尚未纳入公共协议，不能用首帧或参考图数组替代。按实际秒结算仍要求供应商返回可信计量；缺少 `usage.duration_seconds` 时保留待审，不能伪造请求秒数。上游交付失败造成的采购损失仍需独立对账，本轮不改客户退款和财务政策。
